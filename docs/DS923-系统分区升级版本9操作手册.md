# DS923+ 系统分区升级到版本9 (8GB) 完整操作手册

## 概述

将分区布局从当前的自定义布局升级到 DSM 官方版本 9 布局：
- p1 (root): 2.4GB → **8GB**
- p2 (swap): 无 → **2GB**（恢复）
- reserved: **128MB**（恢复）
- p5 (data): 起始从 sector 9453280 移至 ~21235712

**总耗时**: ~3-4 天（主要等待 md2 重建）
**风险**: 处理期间 RAID 降级，无法容忍额外硬盘故障

## 硬件信息

| 盘位 | 设备 | 序列号 | 型号 |
|------|------|--------|------|
| Bay 1 | sata1 | WD-CA2BZ4ZL | WD80EFZZ |
| Bay 2 | sata2 | WD-RD1TX5RD | WD80EFPX |
| Bay 3 | sata3 | WD-CA3B9T5K | WD80EFZZ |
| Bay 4 | — | 空 | — |

## 当前 RAID 状态

- md0: RAID1 (系统), 4.51GiB, [UUU_], sata{1,2,3}p1
- md1: 已不存在（swap 被移除）
- md2: RAID5 (数据), 14.55TiB, [UUU], sata{1,2,3}p5, superblock v1.2

## 存储栈

```
btrfs (/volume1, 14.54TiB, 3.96TiB used)
  ↓  cachedev_0 (flashcache-syno DUMMY)
  ↓  /dev/vg1/volume_1 (LV, 3812864 LE)
  ↓  VG vg1 (PV=/dev/md2, PE=4MB, 总3813087 PE, 末尾空闲220 PE)
  ↓  md2 (RAID5, per-member 7809203456 KB)
```

## Phase 0: 准备和备份

```bash
# 以 root 登录
ssh -o PasswordAuthentication=no -i ~/.ssh/id_ed25519 root@192.168.3.23

# 备份关键配置
tar -czf /volume1/system_backup_pre_v9_$(date +%Y%m%d_%H%M%S).tar.gz \
  /etc /etc.defaults /root 2>/dev/null
echo "备份完成: $?"

# 确认所有 RAID 健康
cat /proc/mdstat
# 期望: md0 [UUU_], md2 [UUU]
# 如果 md2 不是 [UUU]，停止操作，等待修复

# 确认 btrfs 健康
btrfs device stats /volume1
# 期望: 所有计数器为 0
```

**检查点**: md2 必须处于 clean [UUU] 状态才能继续。

## Phase 1: 缩小存储栈（为新分区腾出空间）

新的 p5 分区每成员比当前小约 5.89GB。需要先从上到下缩小存储栈。

### 1.1 缩小 btrfs (在线，安全)

```bash
# 当前 btrfs 设备大小: 14.54TiB, 已用 3.96TiB
# 缩小 17GB（留足余量）
btrfs filesystem resize 1:-17G /volume1

# 验证
btrfs filesystem show /volume1
# 期望: devid 1 size 约 14.52TiB
```

### 1.2 缩小 LV

```bash
# 当前 LV: 3812864 LE = 14.54TiB
# 缩小 17GB = 4352 LE
# 注意: btrfs 已经缩小，LV 末端 17GB 不再被文件系统使用

lvreduce -f -L -17G /dev/vg1/volume_1

# 验证
lvs
# 期望: volume_1 约 14.52TiB
```

### 1.3 缩小 PV

```bash
# LV 缩小后，PV 末端有更多空闲 PE
# 先查看当前状态
pvdisplay -m /dev/md2 | tail -10
# 期望: FREE 区域在末尾

# 计算新 PV 大小:
# md2 将缩小到 per-member 7803000000 KB
# md2 总 = 2 × 7803000000 = 15606000000 KB
# PV 可用 PE = 15606000000 / 4096 ≈ 3808593
# 我们需要 3808515 PE (3 reserved + 3808512 volume_1)
# 3808515 < 3808593 ✓

pvresize --setphysicalvolumesize 15606000000K /dev/md2

# 验证
pvs
# 期望: PV 大小约 14.53TiB
```

### 1.4 缩小 md2

```bash
# 设置 md2 每成员使用量为 7803000000 KB（新 p5 可容纳）
mdadm --grow /dev/md2 --size=7803000000

# 验证
mdadm --detail /dev/md2 | grep -i 'size'
# 期望: Used Dev Size 约 7803000000
# Array Size 约 15606000000

# 确认存储池仍然可用
df -h /volume1
btrfs filesystem show /volume1
```

**检查点**: /volume1 仍然可访问且数据完整。如有任何错误，停止操作。

## Phase 2: 逐盘重新分区

对每块硬盘执行: 移出 RAID → 用 synopartition 重分区为版本9 → 重新加入 RAID。

### 2.1 处理 sata1 (Bay 1, WD-CA2BZ4ZL)

```bash
# ===== 从 RAID 中移除 =====
mdadm /dev/md0 --fail /dev/sata1p1
mdadm /dev/md0 --remove /dev/sata1p1
mdadm /dev/md2 --fail /dev/sata1p5
mdadm /dev/md2 --remove /dev/sata1p5

# 确认 RAID 状态（降级但可用）
cat /proc/mdstat
# 期望: md0 [_UU_] 2/4, md2 [_UU] 2/3

# ===== 重新分区为版本9 =====
# 先查看当前分区
parted /dev/sata1 unit s print

# 使用 synopartition 重分区（index 15 = 版本9, 多Bay）
/usr/syno/sbin/synopartition --part /dev/sata1 15

# 验证新分区布局
parted /dev/sata1 unit s print
# 期望:
#   p1: ~2048s 到 ~16779263s (8GB, raid 标志)
#   p2: ~16779264s 到 ~20973567s (2GB, raid 标志)
#   p5: 某个起始 到 磁盘末尾 (data, raid 标志)

# ★ 关键验证: 确认 p5 存在且合理
/usr/syno/sbin/synopartition --check /dev/sata1
# 期望: "partition layout is version 9"

# ===== 重新加入 RAID =====
# 加入 md0
mdadm /dev/md0 --add /dev/sata1p1

# 加入 md2
mdadm /dev/md2 --add /dev/sata1p5

# 监控重建进度
cat /proc/mdstat
# md0 重建很快（几分钟）
# md2 重建非常慢（12-24小时）

# 持续监控（另开终端或定期检查）
watch -n 60 cat /proc/mdstat
```

**等待**: md0 和 md2 都必须完全重建完毕后再处理下一块盘！
md2 重建可能需要 **12-24 小时**，请耐心等待。
确认方式: `cat /proc/mdstat` 显示 md2 为 `[UUU]` 而非 `[UU_]`。

### 2.2 处理 sata2 (Bay 2, WD-RD1TX5RD)

**前提**: md0 和 md2 已完全重建 [UUU] 后才执行！

```bash
mdadm /dev/md0 --fail /dev/sata2p1
mdadm /dev/md0 --remove /dev/sata2p1
mdadm /dev/md2 --fail /dev/sata2p5
mdadm /dev/md2 --remove /dev/sata2p5

cat /proc/mdstat  # 确认降级但可用

/usr/syno/sbin/synopartition --part /dev/sata2 15

parted /dev/sata2 unit s print                     # 验证布局
/usr/syno/sbin/synopartition --check /dev/sata2     # 验证版本9

mdadm /dev/md0 --add /dev/sata2p1
mdadm /dev/md2 --add /dev/sata2p5

# 等待完全重建（又需 12-24 小时）
watch -n 60 cat /proc/mdstat
```

### 2.3 处理 sata3 (Bay 3, WD-CA3B9T5K)

**前提**: md0 和 md2 已完全重建 [UUU] 后才执行！

```bash
mdadm /dev/md0 --fail /dev/sata3p1
mdadm /dev/md0 --remove /dev/sata3p1
mdadm /dev/md2 --fail /dev/sata3p5
mdadm /dev/md2 --remove /dev/sata3p5

cat /proc/mdstat

/usr/syno/sbin/synopartition --part /dev/sata3 15

parted /dev/sata3 unit s print
/usr/syno/sbin/synopartition --check /dev/sata3

mdadm /dev/md0 --add /dev/sata3p1
mdadm /dev/md2 --add /dev/sata3p5

# 最后一轮重建
watch -n 60 cat /proc/mdstat
```

## Phase 3: 重建 md1 (swap)

所有盘处理完毕后，每块盘都有新的 p2 (2GB swap)。

```bash
# 创建 md1 RAID1 (swap)
mdadm --create /dev/md1 --level=1 --raid-devices=4 \
  --metadata=0.90 \
  /dev/sata1p2 /dev/sata2p2 /dev/sata3p2 missing

# 初始化 swap
mkswap /dev/md1

# 启用 swap
swapon /dev/md1

# 验证
free -h
# 期望: Swap 显示约 2GB
cat /proc/mdstat
# 期望: md1 存在且为 [UUU_]

# 更新 raidtab（让 DSM 知道 md1 存在）
# DSM 可能在重启后自动更新，先检查
cat /run/synostorage/raidtab
```

## Phase 4: 扩展 md0 和系统文件系统

```bash
# 确认所有 md0 成员都是新的 8GB 分区
mdadm --detail /dev/md0
# 期望: 3 个 active sync 成员

# 扩展 md0 到最大
mdadm --grow /dev/md0 --size=max

# 等待 RAID resize（应该很快）
cat /proc/mdstat

# 扩展 ext4 文件系统
resize2fs /dev/md0

# 验证
df -h /
# 期望: 大小约 7.x GB（8GB 减去 ext4 开销和 RAID 元数据）
```

---

## Phase 5: 扩展存储栈回去

现在 md2 的所有成员都是新（较小的）p5 分区，可以让 md2 使用完整空间。

```bash
# 扩展 md2 到每成员最大
mdadm --grow /dev/md2 --size=max
mdadm --detail /dev/md2 | grep -i size

# 扩展 PV
pvresize /dev/md2
pvs  # 验证

# 扩展 LV 到填满 VG
lvextend -l +100%FREE /dev/vg1/volume_1
lvs  # 验证

# 此时 cachedev_0 DM 表可能需要更新
# 最安全的方式: 重启 NAS，让 DSM 自动处理所有 DM 层和挂载
# 或者手动扩展 btrfs:
btrfs filesystem resize 1:max /volume1
btrfs filesystem show /volume1
```

## 紧急回滚

如果在 Phase 2 处理中出现严重问题（如 md2 无法重建）：
1. 不要继续处理其他盘
2. 如果 md2 是 degraded 但可用 [UU_]，数据仍可访问
3. 可以从剩余健康成员手动恢复数据到 /volume1
4. 联系 Synology 技术支持寻求帮助

## 注意事项

1. **不要同时处理两块盘** — 等一块完全重建后再处理下一块
2. **处理期间不要断电** — 使用 UPS 保护
3. **不要在处理期间安装/卸载 DSM 包**
4. **定期检查重建进度** — `cat /proc/mdstat`
5. **处理完毕后建议重启一次** — 让 DSM 完全识别新布局
