# lanbook 1.11.1

针对 Windows 自启守护重复累积的独立补丁，包含此前未纳入 1.11.0 的单实例修订。macOS / Linux 自启方式不变，依赖不变。

## 修复

- VBS 继续以隐藏窗口启动守护，但改为等待 CMD 退出，让计划任务在守护运行期间保持 Running。
- 显式设置计划任务 `MultipleInstances=IgnoreNew`，登录 / 解锁重复触发时不排队、不并行。
- 守护进入循环前持有数据目录级 `.autostart-guardian.lock` 独占写句柄，覆盖服务运行、端口待命和失败退避。竞争失败直接退出，避免累积额外 CMD / VBS / ping 进程。
- 数据目录切换失败时立即退出，避免从错误工作目录继续常驻。

锁以数据目录而不是任务名为粒度，也覆盖扩展直接启动 VBS 的入口。锁文件可以一直存在，持锁取决于句柄共享规则，注册 / 卸载不会删除它。守护及继承句柄的子进程全部退出后由系统释放；不能仅凭文件存在判断正在运行，也不能删除文件来抢锁。

## 升级注意

**更新 npm 包本身不会清理已经运行的旧守护，也不会自动重写现有自启脚本。**

1. 停止旧守护与服务，并核实相关进程确实退出；停止标记可能要等当前待命 / 退避结束，不能只以标记存在作为退出依据。
2. 使用新版 `lanbook autostart` 重新生成包装脚本、注册自启任务。
3. 只启动一次，再检查状态。不要只杀 `ping.exe`，它只是旧守护的延时子进程。

本次提交 / 版本准备不自动改动本机现有自启任务或运行中的守护。详细设计与现场依据见 [ADR-0005](../adr/0005-cross-platform-autostart.md#单实例保护后续修订)。

## 验证边界

新增测试覆盖生成器契约，以及 Windows 下并发入口、正常退出 / 强杀后重新获得锁和服务运行 / 待命 / 退避三个阶段的互斥。

本环境仅执行不调用真实系统注册命令的生成器单元测试、安全服务回归与发布包冒烟；真实 CMD / 计划任务并发集成测试未在本环境运行，不能把已有测试用例当作已经通过的实机证明。发布准备不执行 `npm publish`。
